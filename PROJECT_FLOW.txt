===========================================================================
  PROJECT FLOW — Audio-Visual Dialogue Extractor & Timestamp Identifier
===========================================================================

This document walks through the pipeline end-to-end, stage by stage, in
the order execution actually happens.

---------------------------------------------------------------------------
STAGE 0 — USER INPUT
---------------------------------------------------------------------------
The user provides two things:
  - A video source (URL or local file path)
  - A target dialogue phrase to locate inside that video

---------------------------------------------------------------------------
STAGE 1 — MEDIA INGESTION (Hugging Face Space)
---------------------------------------------------------------------------
Rather than the local machine making a direct network request to the
source platform, the video is routed through a Hugging Face Space acting
as an intermediary fetch/upload layer.

Why: direct local downloads from video platforms increasingly hit
bot-detection and request-blocking at the network level (rate limits,
IP flags, JS-challenge walls), which made local-only extraction
unreliable. The Hugging Face Space provides a stable, repeatable path
to acquire the video without the local machine being the one making the
flagged request.

Once acquired, the raw video is handed off to the local pipeline for
processing.

---------------------------------------------------------------------------
STAGE 2 — LOCAL CACHE CHECK
---------------------------------------------------------------------------
Before doing any further work, the pipeline checks the output/ directory
for an existing, non-empty temp_video.mp4 or temp_audio.wav.

  - If found        -> skip ingestion + audio extraction entirely
  - If not found     -> proceed to audio extraction

This avoids re-fetching or re-processing the same media on repeated runs
(e.g. while iterating on a target phrase).

---------------------------------------------------------------------------
STAGE 3 — AUDIO EXTRACTION
---------------------------------------------------------------------------
FFmpeg strips the audio track from the downloaded video and converts it
to a pipeline-friendly format:
  - Mono channel
  - 16kHz sample rate
  - PCM WAV encoding

This normalized format is what Whisper expects for consistent, fast
transcription.

---------------------------------------------------------------------------
STAGE 4 — DEVICE & HARDWARE DETECTION
---------------------------------------------------------------------------
Before transcription starts, the pipeline detects whether a CUDA-capable
GPU is available:
  - GPU available -> load Whisper on CUDA, enable fp16 precision
  - No GPU         -> fall back to CPU execution (fp16 disabled)

---------------------------------------------------------------------------
STAGE 5 — WHISPER SPEECH-TO-TEXT
---------------------------------------------------------------------------
Whisper transcribes the extracted audio with word-level timestamps
enabled, producing an array of:
  { word, start_time, end_time }

If a given segment doesn't return word-level timestamps, the pipeline
falls back to evenly distributing timestamps across that segment's
tokens, so downstream matching always has a timestamp per word.

---------------------------------------------------------------------------
STAGE 6 — FUZZY PHRASE MATCHING (rapidfuzz)
---------------------------------------------------------------------------
The target phrase is compared against sliding windows of transcribed
words:
  - Window size is centered around the target phrase's word count
    (checked across a small range, not just an exact-length window)
  - Each window's text is compared to the target phrase using
    rapidfuzz.fuzz.ratio
  - The highest-scoring window becomes the match, provided it clears
    the configured confidence threshold

This makes matching resilient to minor transcription errors, missing
punctuation, or slightly different phrasing — an exact string match
would fail far more often.

---------------------------------------------------------------------------
STAGE 7 — OPTIMAL FRAME EXTRACTION
---------------------------------------------------------------------------
Using the midpoint timestamp of the matched phrase, the pipeline scans a
small window of frames around that timestamp (e.g. +/- 0.5s) and scores
each one using Laplacian variance (a sharpness/blur metric). The
sharpest frame in that window is selected and saved — this avoids
picking a motion-blurred frame that happens to land exactly on the
matched timestamp.

---------------------------------------------------------------------------
STAGE 8 — OUTPUT
---------------------------------------------------------------------------
The pipeline returns:
  - Formatted timestamp (HH:MM:SS.sss)
  - Frame number
  - Matched dialogue text
  - Match confidence score
  - Frame sharpness score
  - Path to the saved frame image
